# コミットメッセージ生成スキル (Generate Commit Message Skill)

このスキルは、ワークスペースの変更内容を走査し、日本語の Conventional Commits 形式で最適なコミットメッセージを生成するための手順です。実際にコミットは行いません。

## 使用タイミング
- ユーザーが「コミットメッセージを生成して」「gitの変更からコミットメッセージを作って」などと依頼したとき。
- 変更内容を要約し、コミットのためのメッセージを用意したいとき。

## 手順・行動指針

### 1. 変更内容の確認 (走査)
- ワークスペースが Git 管理下にあるか確認し、Gitリポジトリである場合は以下のコマンドを実行して変更内容（差分）を取得します。
  - `git status`
  - `git diff --cached` (ステージ済みの変更がある場合)
  - `git diff` (ステージされていない変更がある場合)
- Git 管理下でない場合、または git コマンドが使用できない場合は、ファイルの一覧や更新日時、ファイル内容の変更箇所を確認して、どのような変更が入ったかを把握します。

### 2. コミットメッセージの生成ルール
生成するコミットメッセージは、以下のルールに厳密に従ってください。

- **言語**: 日本語
- **形式**: Conventional Commits 形式
  - 書式: `<type>(<scope>): <description>` または `<type>: <description>`
  - `<type>` は以下のいずれかを使用します：
    - `feat`: 新機能の追加
    - `fix`: バグ修正
    - `docs`: ドキュメントのみの変更
    - `style`: コードの動作に影響しない変更（ホワイトスペース、フォーマット、セミコロンなど）
    - `refactor`: バグ修正や機能追加を行わないコードのクリーンアップ・再構成
    - `perf`: パフォーマンス向上のためのコード変更
    - `test`: テストの追加や修正
    - `build`: ビルドシステムや外部依存関係の変更
    - `ci`: CI設定やスクリプトの変更
    - `chore`: その他、ソースコードやテストファイルに影響しない雑多な変更（依存関係の更新など）
- **内容の簡潔さ**: description は簡潔かつ具体的に、変更内容が伝わるように日本語で記述します。
- **詳細情報の追加**: 変更内容が多岐にわたる場合や詳細な説明が必要な場合は、ヘッダー行の後に空行を1行挟み、箇条書きで詳細な変更点を日本語で記述します。

### 3. 出力とクリップボードへのコピー
- 生成したコミットメッセージをユーザーに提示します。
- ユーザーの手間を省くため、PowerShell の `Set-Clipboard` などのコマンドを実行して、生成したコミットメッセージをクリップボードに自動的にコピーします。
- **注意**: 実際に `git commit` コマンドを実行してコミットを行ってはいけません。提示されたコミットメッセージを適用するかどうかはユーザーが決定します。
